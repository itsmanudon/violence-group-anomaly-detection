# Measured local cascade demonstration v1

The frozen deployment combines real DCSASS-trained Sultani and RGB
Actor-Transformer models with automatic COCO_V1 people and the validated frozen
C3D/I3D backbones. `configs/surveillance_demo.yaml` pins all five hashes. This
demonstrates working software with weak research models, not reliable deployment.

## Population and selection

Eight clips in `configs/demo_examples.json` come from held-out original sources.
The initial six examples are the first eligible covered clip by ID per label,
at least two seconds long, chosen independently of prediction correctness.
A separate high-confidence behavior mistake was selected after evaluation for
discussion. A supplemental correctly bypassed Normal clip was also selected
post hoc from saved predictions; all seven original cases remain unchanged.
These choices do not change models, thresholds, scientific splits or benchmark
results. Several examples share original sources and are not independent samples.

The cached outputs were generated by genuine `SurveillancePipeline` inference,
not assembled from the separate clip-classification metrics. Window sampling can
therefore produce a different behavior prediction from a middle-frame benchmark.
Each cache binds video bytes, model hashes, preprocessing and routing policy.

| Installed case | Dataset clip label | Actual cascade result | Generation time |
|---|---|---|---:|
| Normal example | Normal | Robbery review alert (false alert) | 2.92 s |
| Abuse example | Abuse | Robbery review alert (wrong behavior) | 1.80 s |
| Assault example | Assault | No anomaly (miss) | 0.16 s |
| Fighting example | Fighting | Robbery review alert (wrong behavior) | 1.16 s |
| Robbery example | Robbery | Robbery review alert | 2.77 s |
| Vandalism example | Vandalism | No anomaly (miss) | 0.21 s |
| Limitation: high-confidence mistake | Fighting | General anomaly; behavior Normal | 1.11 s |
| Normal: no-alert example | Normal | No anomaly; actor analysis bypassed | 0.85 s |

At the frozen 0.5 anomaly threshold, this curated set contains four true anomaly
alerts, one false alert, two missed anomalous clips and one correctly bypassed
Normal clip. These counts describe these chosen cases only; they do not estimate
population precision/recall. The separate subsystem test populations and their
metrics must remain separate.

There are 15 routed windows: 14 covered and one with no detected people. The empty
window in **Normal example** keeps a generic anomaly alert and null behavior
probabilities; other covered windows produce its final Robbery review alert.
This 1/15 unavailable rate is a demonstration-window count, not DCSASS clip
coverage. Dataset detection precision/recall/IoU cannot be measured without GT
boxes. DCSASS also lacks frame-level event annotations, so localization quality
and interval-specific behavior correctness remain unmeasured.

## Latency and real execution checks

Hardware: NVIDIA GeForce RTX 4070 Laptop GPU. A repeated two-second Robbery
input produced exactly identical 32 scores, detector boxes/confidences, six-class
probabilities and final alert on GPU. Its warm second inference analyzed three
windows. Two OpenMP/MKL threads were used in the measurement process.

| Stage | Warm GPU | CPU fallback |
|---|---:|---:|
| Video decoding, including actor windows | 0.201 s | 0.283 s |
| C3D preprocessing | 0.019 s | 0.020 s |
| C3D FC6 | 0.034 s | 2.234 s |
| Sultani scoring | 0.001 s | 0.006 s |
| Actor window preprocessing | 0.075 s | 0.093 s |
| Person detection | 0.426 s | 10.059 s |
| I3D actor features | 0.278 s | 14.603 s |
| Actor-Transformer | 0.010 s | 0.039 s |
| Other overhead | 0.053 s | 0.063 s |
| Total inference | **1.099 s** | **27.400 s** |

Model loading, UI rendering and JSON/download transport are excluded from the
stage table and are recorded separately where applicable. Generation times above
include warm-up differences across processes. These short-clip measurements do
not establish long-video throughput or real-time FPS. CPU execution exercised
all five actual models and retained the Robbery alert; CPU/GPU numerical equality
is not claimed. A real validation no-actor clip independently verified abstention
without running I3D or Actor-Transformer.

The running loopback Gradio API passed cached bypass, cached Robbery, cached
disagreement, genuine live Robbery and genuine uploaded-video requests. It
rendered timelines, reference galleries, interval tables and downloadable result
JSON; source preview and empty-input handling also passed. Uploads preserve
original bytes and do not require FFmpeg transcoding. Chrome control later
recovered and the Normal video played to its end. Cached Robbery and anomaly/Normal
disagreement were visually inspected with timelines, overlays and interval evidence.
Fixed the dark table-header contrast and cleared stale evidence when sources
change; model probabilities are visibly marked uncalibrated. Screenshot:
`outputs/demo/visual-disagreement.jpg`. Automated file selection requires a Chrome
extension permission that was left unchanged; manual upload inspection remains
a presentation check, while the genuine live-upload API path has passed.

## Local evidence and commands

- `runs/dcsass/integration-demo-v1.json`: original seven cache generation results.
- `runs/dcsass/normal-bypass-receipt.json`: supplemental case receipt.
- `runs/dcsass/real-runtime-verification.json`: deterministic GPU, no-actor and CPU checks.
- `runs/dcsass/demo-api-validation.json`: actual Gradio callback/transport results.
- `runs/dcsass/demo-asset-verification.json`: verified deployment model identities.
- `outputs/demo/examples/`: actual per-video outputs and detailed interval evidence.

```powershell
.\.venv\Scripts\python.exe scripts/verify_demo_assets.py
.\.venv\Scripts\python.exe scripts/cache_demo_examples.py --output runs/dcsass/demo-cache-verification.json
.\.venv\Scripts\python.exe -m surveillance.demo
```

While the server runs, `python scripts/validate_demo_api.py` checks its public
API. The cache generator reuses matching existing caches without loading models;
it rejects changed identities. Use a new receipt output path to preserve history.
# Historical deployment version

The measurements in this report use the original DCSASS-trained anomaly scorer and remain
unchanged. Its launch configuration is preserved as
`configs/surveillance_demo_dcsass_v1.yaml`. The common default configuration now
uses the validation-selected UCF scorer, versioned separately in
`configs/surveillance_demo_ucf_v1.yaml`; see
[the UCF results](sultani-ucf-results-v1.md). Do not attribute these historical
latencies or example outcomes to the newer model version.
